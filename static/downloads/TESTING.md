# 测试说明

> 题目要求：至少覆盖**主链路**、**数据缺失/接口失败**、**极端或合规边界**场景。

## 运行方式

```bash
cd evident
python3 tests.py        # 24 项断言，退出码 0 表示全通过
```

## 覆盖矩阵

### 1. 主链路（10 项）—— 取数 → 原子化 → 事件归并 → 冲突/状态仲裁

| 断言 | 验证点 |
|---|---|
| 10 条原始记录全部原子化 | Atomize 阶段无丢失 |
| 归并为 3 个事件（无过合并/漏合并） | **事件归并正确性**（核心难点） |
| 检测到传闻 vs 官方否认冲突 | 冲突检测生效 |
| 覆盖 DENIED/CONFIRMED/RUMORED 状态 | 状态机多态正确 |
| 事件标题取最初来源叙事 | "看清最初来源" |
| 归并依据可解释 | 结论可审计 |
| 每条证据保留原始记录 ID | **可溯源到原始字段** |
| 更正记录标记「发布后被修改」 | `disclose_time != update_time` 生效 |
| 来源权重正确（官方 1.0 > 传闻 0.06） | **证据权重**计算正确 |
| 标的索引包含三个关注标的 | 与关注标的的关系 |

### 2. 数据缺失与降级（4 项）

| 断言 | 验证点 |
|---|---|
| 空数据时 `health.degraded=True` | **不静默生成正常结论** |
| 空数据时携带警告文案 | UI 可向用户显式告警 |
| 空数据时不伪造事件 | 无数据就说无数据 |
| 截断标志（`was_truncated`）透传到 UI 层 | 上游截断不被隐藏 |

> 设计依据：扶摇官方文档明确「空列表也可能表示服务降级，不能据此断言期间没有异动」。

### 3. 接口失败（2 项）

| 断言 | 验证点 |
|---|---|
| `real` 模式 + 无效 key → 显式失败，不伪造 | 调用失败必须暴露 |
| `auto` 模式无 key → 自动降级 mock 并带警告 | 降级行为对用户可见 |

实测证据（真实网络调用）：
```json
{"code":2003,"message":"Invalid or revoked API key"}
```

### 4. 合规边界（8 项）

| 断言 | 验证点 |
|---|---|
| 输出不含「建议买入 / 建议卖出 / 必涨 / 必跌 / 保证收益」 | **不得输出确定性涨跌预测与买卖建议** |
| 证据分类覆盖事实/观点/传闻 | 事实与推断可区分 |
| 来源层级覆盖官方到传闻 | 证据权重体系完整 |
| 所有结论可回溯原始 ID | 结论可回到原文 |

## 性能测试（真实数据）

首屏需打 7 个上游接口，为此做了并行取数、特征预计算、TTL 缓存三层优化。

**各接口基线耗时（串行实测）**

| 接口 | 耗时 | 数据量 |
|---|---|---|
| 异动解读 | 1.79s | **4.2 MB**（最大瓶颈） |
| 个股新闻 600519.SH | 0.52s | 24 KB |
| 其余 5 个接口 | 0.16~0.18s | <25 KB |
| 串行合计 | 3.17s | |

**优化前后对比**

| 阶段 | 优化前 | 优化后 |
|---|---|---|
| 取数（7 接口） | 3.17s（串行） | 1.96s（并行） |
| 归并 + 仲裁 | 6.15s | **0.13s**（特征预计算） |
| **首次总耗时** | **8.77s** | **2.33s** |
| 缓存命中 | 无缓存 | **0.032s** |

**公网实测**

| 场景 | 耗时 |
|---|---|
| 首次加载（回源） | 1.69s |
| 缓存命中 | 0.42s |
| 强制刷新（`?refresh=1`） | 1.50s |

**关键验证点**
- 失败结果不写入缓存（避免把瞬时故障固化 90 秒）。
- `refresh=1` 可绕过缓存强制回源，页面「刷新」按钮即走此路径。
- `health.cache_hit` / `cache_age_s` 会透传到前端并显示，缓存状态对用户可见。
